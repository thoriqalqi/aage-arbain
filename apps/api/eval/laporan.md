## Konfigurasi mode LLM

- **Model:** `deepseek-v4.1-flash:free (juri ClaimGuard: deepseek-v4.1-flash:free)`
- **Provider:** TokenHarbor (`https://tokenharbor.ai/v1`, endpoint OpenAI-compatible), dipanggil langsung tanpa LiteLLM.
- **Panggilan LLM:** 30 · berhasil 30 · ERROR 0 · kena rate limit 0 · retry 0 · jeda 4 dtk antar panggilan.
- **Peran LLM di 80 pesan:** jawaban disusun LLM 8 · intent ditentukan LLM 11 · juri ClaimGuard LLM 1 · fallback_template (draf LLM diganti karena ClaimGuard) 0.
- **Harga token (PERKIRAAN):** LLM_PRICE_IN_USD_PER_M=0,30 dan LLM_PRICE_OUT_USD_PER_M=2,50 (nilai bawaan, belum disesuaikan). Model `:free` sebenarnya gratis, jadi biaya di Ledger lebih tinggi dari biaya nyata.

## Keterbatasan (dibaca sebelum memakai angka di atas)

1. **`jawaban_diharapkan` mengacu ke katalog SIMULASI** (nomor BPOM `SIM26xxxx` fiktif). Angka belum berlaku untuk katalog asli mitra.
2. **Dataset ditulis manual dan independen** — pertanyaan TIDAK dibangkitkan dari file katalog yang dipakai template, sehingga tidak melingkar seperti eval lama (100%). Fakta jawaban yang diharapkan tetap diambil dari katalog.
3. **LLM hanya dipakai di 4 titik** (router cadangan, jawaban tanya-produk, jawaban dokumen/kebijakan umum, juri ClaimGuard untuk kalimat ambigu). Intent harga, izin edar, kebijakan, nego, pesanan, klaim, dan medis dijawab aturan di KEDUA mode — karena itu selisih template vs LLM kecil.
4. **Router dan juri memakai model yang sama** (`deepseek-v4.1-flash:free`).
5. **API key sempat dibagikan di chat** (Gemini dan TokenHarbor) — harus dirotasi sebelum pilot.
6. **Eval Gemini sebelumnya tidak dipakai:** kuota gratis habis setelah ±20 panggilan (15 ERROR); hasilnya tertimpa run ini.
7. Penilaian otomatis berbasis pencocokan fakta & regex. Ke-25 balasan klaim dibaca manual (lihat daftar lengkap).
8. Satu run per mode; model LLM tidak deterministik sepenuhnya, hasil bisa sedikit berbeda bila diulang.
